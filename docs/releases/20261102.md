# Browser analysis recovery — 2 November 2026

The public Analyse patient workflow failed because its manifest requested 21 source files under `/src/`, while the static artifact deliberately excluded source directories. The page now loads a generated `js/engine_sources.json` containing only the analysis dependency closure. Every file is verified against the versioned SHA-256 manifest before Python starts. Backend API code, databases, credentials and recovery artifacts remain excluded.

Both the public artifact builder and the container build generate this bundle. Packaging refuses stale manifests, source symlinks, untracked dependencies and pre-supplied bundles. A regression reconstructs the engine from the public artifact alone and runs the lung-nodule, FIT and completed-INR examples without importing the original checkout. Loader tests reject missing, altered, extra and redirected assets before Python starts.

Analysis result rule names, event labels, missing steps and urgency messages follow the selected English/Korean interface. Engine evidence and original passages remain accessible unchanged in labelled sections. Empty results explicitly require review of the complete original report; an unread patient or event population is identified as incomplete analysis coverage. These display changes do not modify clinical rules or infer a new finding.

## Verification and limits

- Full offline regression: 1,515 tests and 239 subtests passed; Git-dependent tests were run separately. Optional imaging-model performance was not tested.
- Frozen development evaluation: 753 reused developer/AI-authored synthetic reports; 467 matched obligations, 37 extras, 115 missed (including abstention), precision 0.9266, recall 0.8024. These are regression measurements, not independent clinical accuracy. Sixty timeline cases yielded 35 exact status cases and 53/78 strict status comparisons.
- A de-identified MIMIC-CXR report published in MIT's documentation was processed locally through the browser. One event yielded zero tracked obligations, demonstrating why an empty result cannot mean a normal report. This was a processing check, not a labelled clinical evaluation.
- HL7's public FHIR R4 CBC example lacks the referenced Patient resource. Unmodified input yields zero patients/events and a processing warning. The interface identifies incomplete coverage. It is not evidence of normal laboratory results.
- The official NLM Open-i API and report-archive URLs returned HTML instead of usable dataset responses during this run; no new Open-i evaluation is claimed.
- No clinical engine source was modified. Independent clinician review, held-out patient/site/time/language evaluation, multiple-lesion and source-bound graph identity, false-closure/workload assessment, model/OCR/raw-image validation, hospital integration and prospective silent evaluation remain outstanding. No clinical-use approval or highest-accuracy claim is made.

Public sources: [MIMIC-CXR documentation](https://mimic.mit.edu/docs/iv/modules/cxr/), [HL7 CBC example](https://hl7.org/fhir/R4/diagnosticreport-example.json.html), [NLM Open-i](https://openi.nlm.nih.gov/faq). Raw public report data was kept outside Git and the deployed static artifact. Test metadata dates are artificial and do not assert original study dates.
